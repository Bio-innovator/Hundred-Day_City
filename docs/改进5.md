## 1. 弹窗系统：层级、单例复用与状态清理（P0）

### 1.1 现象（AI 试玩反馈）

- 打开「设置」后再点「科技树 / 成就」，新内容与旧内容叠在一起，关闭按钮被遮住或点不到
- 切换「设置」「网络」「终局」时，标题、关闭按钮与主体内容错位
- 关闭按钮有时"点透"，点上去操作到了背后的页面

### 1.2 根因（已定位，共 4 条）

1. **单例复用，只换内容不清状态**
   `index.html:97` 只有一个 `<dialog id="game-dialog">`，所有面板共用。`openDialog()`（`hud.js:457`）只改 `dialogMode`、标题，再 `renderDialog()` 覆盖 `innerHTML`，**没有清 `scrollTop`、没有清 `pendingImport`、没有解绑上一次临时监听**。上一次滚到中间的设置页，切到成就后仍然停在中间。

2. **没有监听 `close` 事件 → `dialogMode` 残留**
   `hud.js:480` 只在 `closeDialog()` 里把 `dialogMode` 置 null。用户按 **Esc** 或点 backdrop 时，浏览器直接关闭 `<dialog>`，`closeDialog()` 不执行，于是：
   - `dialogMode` 还是旧值
   - `render()`（`hud.js:243`）会继续往**已关闭**的 dialog 写内容
   - 下次点另一个入口时，若命中"已 open 就跳过 showModal"的分支，可能不重新入栈

3. **教程层被压在弹窗下面**
   `openDialog("settings")` 会执行 `this.tutorial?.start(false)`（`hud.js:464`）。教程遮罩是 `position: fixed; z-index: 100`（`style.css:404`），而 `<dialog>` 使用浏览器 **top layer**，永远在普通 z-index 之上。结果：教程卡片被压在弹窗底下，只剩遮罩的"洞口"露出来，正好造成"关闭按钮被遮挡 / 点透"的观感。

4. **两个 modal 可能同时打开**
   `#offline-dialog` 与 `#game-dialog` 是独立的 `<dialog>`。若离线弹窗未处理，用户又触发别的入口，就出现两套 backdrop 叠着。

### 1.3 方案

**A. 状态机化，先关后开**

```js
openDialog(mode) {
  if (this.elements.dialog.open) this.elements.dialog.close();  // 先关，触发 close 事件
  this.resetDialogState();                                      // 清 mode / pendingImport / 临时监听
  this.dialogMode = mode;
  ...
  this.elements.dialogContent.scrollTop = 0;
  this.elements.dialog.showModal();
}
closeDialog() { this.resetDialogState(); if (open) close(); }

// 关键：接住 Esc 与 backdrop 的关闭
this.elements.dialog.addEventListener("close", () => this.resetDialogState());
```

**B. 层级表写进 CSS 变量，一处定义**

| 层 | z-index | 说明 |
|----|---------|------|
| `dialog`（原生 top layer） | 由浏览器管理 | 永远最高 |
| 教程遮罩 / 卡片 | 只允许出现在**无弹窗**时 | 若弹窗已开，教程自动暂停 |
| 成就卡片 | 8000 | 非模态，允许在弹窗之上 |
| toast | 9000 | 最高 |

**C. 教程与弹窗互斥**（直接解决"遮挡"）

- `openDialog()` 时若教程正在跑：**暂停教程**（保留进度），关弹窗后恢复
- 教程运行中，所有 `data-open` 按钮**不响应**（或先关教程再开弹窗，二选一，必须明确）
- `openDialog("settings")` 里那句 `tutorial.start(false)` 删掉：教程不该由"打开设置"触发

**D. 焦点与可访问性**

- 打开时记录 `document.activeElement`，关闭后 `focus()` 回去
- dialog 内第一个可交互元素自动聚焦（`autofocus` 或手动 `focus()`）
- 关闭按钮 `aria-label` 保持，Esc 作为第二条关闭路径（两条路径必须走同一个 `resetDialogState`）

**E. 同一入口重复点击**

- 已打开同一 mode：不重开，只滚到顶部（避免"点两下闪烁"）
- 已打开不同 mode：先关再开（保留过渡，不做无动画硬切）

### 1.4 验收

- 设置 → 科技树 → 成就 → 网络 → 终局，连续切换 10 次：标题/内容/关闭按钮始终对得上，滚动位置每次归零
- 用 Esc 关闭后立刻再开另一个面板：内容正确、不残留上一次的导入预览
- 设置打开时不会冒出教程卡片
- 弹窗打开时点遮罩一次即关，不会"关一层还剩一层"

## 2. 快捷键体系（P1）

### 2.1 现状（先纠正一条误判）

AI 试玩报告说"暂停必须点进二级设置"——**不准确**：`hud.js:229-236` 已经实现了空格暂停与 `B` 键。

但它确实有三个真问题：

1. **没有 1/2/4 调速快捷键**（只能进设置里点）
2. **弹窗打开时空格仍然生效**——在设置面板里按空格会直接暂停/继续，且如果焦点正好在「暂停模拟」按钮上，可能触发"按钮自身 + 快捷键"两次切换
3. **没有快捷键帮助页**，玩家不知道有这些键；`B` 键调用的是 `toggleMobilePanel("build")`，桌面端语义不对

### 2.2 键位表

| 键 | 作用 | 备注 |
|----|------|------|
| `Space` | 暂停 / 继续 | 已有，需修冲突 |
| `1` / `2` / `4` | 切换到 1× / 2× / 4× | 新增 |
| `B` | 开/关建造面板 | 桌面端聚焦左栏，移动端开抽屉 |
| `Esc` | 关闭弹窗 / 取消选中 / 退出建造 | 统一到同一出口 |
| `R` | 复原视角（居中 + 100%） | 见 §7 |
| `?` 或 `H` | 快捷键与操作说明 | 新增 |
| `Ctrl + 0` | 视角复原（备用） | 与浏览器习惯一致 |

### 2.3 实现要点

```js
document.addEventListener("keydown", (event) => {
  const tag = document.activeElement?.tagName;
  if (["INPUT", "TEXTAREA", "SELECT"].includes(tag)) return;   // 输入框内不拦截
  if (this.dialog.open) {                                       // 弹窗内只保留 Esc
    if (event.key === "Escape") this.closeDialog();
    return;
  }
  if (event.code === "Space") { event.preventDefault(); this.togglePause(); }
  if (["Digit1", "Digit2", "Digit4"].includes(event.code) && !event.ctrlKey && !event.metaKey) {
    this.changeSetting("speed", Number(event.code.slice(-1)));
  }
  ...
});
```

- 数字键只在**非输入框、非弹窗、非 Ctrl/Alt** 时生效
- 所有快捷键触发后调用 `event.preventDefault()`，避免空格滚页、`?` 打不出字
- 暂停状态变化后**统一刷新所有暂停按钮**（顶栏 + 设置里若有），不要像现在 `togglePause()` 那样只 `querySelector("#settings-pause")`
- 帮助页放设置「关于」或独立 `H` 弹窗，列全表，别让玩家猜

### 2.4 验收

- 空格暂停/继续；连按 1/2/4 顶栏流速指示同步
- 在设置面板里按空格不改变暂停状态；在存档文本框里按空格能正常输入空格
- `?` 能打开快捷键说明，Esc 关掉
- 焦点停在任意按钮上时，空格只触发一次

## 3. 建筑网格：悬停高亮与放置预览（P1）

### 3.1 现状

`grid.js` 只有 `pointerdown` 建造、`pointermove` 处理双指缩放（`grid.js:54`），**没有任何 hover 状态**。地图上既没有格子边框，也没有"这个位置会建成什么、占几格、能不能建"的预览。

后果：连续放置时容易偏一格；多尺寸建筑（5×5 发射台）根本看不出落点；缺料/不可建也没有即时反馈。

### 3.2 方案

**A. 常驻网格线（弱）**

- 1px、透明度 ≤ 12% 的格线，只在缩放 ≥ 100% 时绘制，< 100% 时隐藏（避免糊成一片）
- 不参与每帧重绘：画进地形离屏 canvas

**B. 悬停高亮（强）**

- 鼠标下的格子：1px 青色描边 + 极淡填充
- 已选中建造项时：绘制**完整占地轮廓**（按 `size.w × size.h`）+ 半透明幽灵精灵
- 合法性判定：
  - 可建 → 青色
  - 不可建（占用 / 未解锁格 / 越界 / 缺料）→ 红色描边，且**不放幽灵**
- 拖动地图时不显示预览（位移 > 4px 就隐藏）

**C. 性能**

- hover 只重绘 overlay 层（独立 canvas 或 `drawing` 层的 dirty rect），**不要重绘地形缓存**
- `pointermove` 节流到 `requestAnimationFrame`，不要每个事件都画
- 移出画布清空 hover 状态

**D. 触屏兜底**

- 触屏没有 hover：点一下先"选中格子"显示预览，再点一次确认建造（或保留现有单击即建，但显示 200ms 的落点反馈）

### 3.3 验收

- 鼠标移动时高亮跟手，不闪烁、不掉帧
- 5×5 建筑能看清占哪几格；不可建位置立刻变红
- 拖动地图时不会误显示建造预览
- 缩放 < 100% 时不出现糊成一团的格线

## 5. 时间尺度：一天 60 → 90 秒（P1）

### 5.1 现状与问题

`maps.js:3`：`export const DAY_SECONDS = 60;`

60 秒/天意味着：

- 建两座太阳能板（各 6 秒）+ 一座废料场，抬头已经过了 2 天
- 第一次脉冲在 DAY 12 左右，**第一次玩的人还没搞懂加工链就被打**
- 100 天 = 100 分钟，节奏偏赶

### 5.2 方案

**改 `DAY_SECONDS = 90`**，其余天数逻辑不动。

| 项 | 60 秒/天 | 90 秒/天 |
|----|----------|----------|
| 一天 | 1 分钟 | 1.5 分钟 |
| 首次脉冲（DAY 12） | 约 12 分钟 | 约 18 分钟 |
| 100 天 | 100 分钟 | 150 分钟 |
| 建造 6 秒的建筑 | 占 0.1 天 | 占 0.07 天 |

### 5.3 必须一起改的三处（否则会出新问题）

1. **旧存档迁移**
   `elapsed` 保留不动，`day` 会变小（原来 DAY 60 → 现在 DAY 40）。
   但 `nextPulseDay`、`lastWarningDay` 是**按天存的**，不换算就会让"下一次脉冲"凭空延后 1.5 倍。
   迁移时按 `× 2/3` 取整缩放：

```js
nextPulseDay = Math.max(day + 1, Math.round(nextPulseDay * 60 / 90));
lastWarningDay = Math.round(lastWarningDay * 60 / 90);
```

2. **按秒计时的灾变会变密**
   风暴 `stormInterval = [180, 300]` 秒、脉冲外的陨石 45 秒、腐蚀按 dt——这些都是**秒**。
   原来 180–300 秒 = 3–5 天，改 90 秒/天后变成 **2–3.3 天**，玩家体感"风暴更频繁"（这正好和上一轮"灰烬风暴太频繁"的反馈撞车）。
   处理：把按秒的间隔一起 ×1.5，或改成按天配置再换算成秒。**推荐后者**（`stormIntervalDays: [3, 5]` → 秒）。

3. **流速档位变成补偿工具**
   90 秒/天会让整局变长 1.5 倍。保留 1×/2×/4×，并在快捷键里暴露（§2），让赶时间的玩家自己加速，而不是把基准值调回去。

### 5.4 验收

## 6. 暂停按钮外置（P1）

### 6.1 现状

暂停按钮只存在于 **设置 → 游戏** 标签页里（`hud.js:560`，`id="settings-pause"`）。顶栏没有，移动端底栏也没有。

`togglePause()`（`hud.js:259`）还有个隐患：它只更新 `#settings-pause` 的文字。一旦按钮被移到顶栏，设置里那份就不刷新，两处状态会不一致。

### 6.2 方案

**A. 顶栏常驻按钮**

- 位置：顶栏右侧，紧邻「科技树」，图标 `⏸` / `▶`，`aria-pressed` 表示当前是否暂停
- 暂停时按钮变琥珀色 + 顶栏加一条 2px 顶部色带，全屏可见"时间是停的"
- 移动端：底栏第 6 个位置放暂停（或地图区右下角悬浮）

**B. 状态刷新统一化**

```js
// 不要在 togglePause 里 querySelector 单个按钮
syncPauseUI() {
  document.querySelectorAll("[data-pause]").forEach((btn) => {
    btn.textContent = this.state.settings.paused ? "▶" : "⏸";
    btn.setAttribute("aria-pressed", String(this.state.settings.paused));
  });
  document.body.classList.toggle("paused", this.state.settings.paused);
}
```

- `togglePause()` / `SET_SETTING(paused)` / 读档后 都调 `syncPauseUI()`
- 设置页里那份**删掉**（避免两套 UI），或保留为只读状态显示

**C. 视觉**

- `body.paused` 时给 `#game-canvas` 加 8% 灰罩 + 「已暂停」角标（不要用模糊，会破坏像素感）
- `prefers-reduced-motion`：只变色，不呼吸

### 6.3 验收

- 顶栏一键暂停；空格同步；设置里不再有第二个暂停按钮
- 暂停时画布明显"停住"（灰罩 + 角标），不只是资源不动
- 刷新页面后按钮状态与 `settings.paused` 一致

## 8. 设施连通性：未接入网络则待机（P0）

### 8.1 现状：这条设定丢了

- `state.js:120` 的 `isOperational()` 只看 `hp > 0 && buildRemaining <= 0`
- `production.js` 直接结算，没有连通判断
- `drawAdjacencyNetwork()` 只画线，不参与逻辑

### 8.2 规则（已确认：待机不耗电、不产出）

**网络源**：灰烬平原 = 运算中心；其它地图 = 中转站；地下层 = 竖井升降机或信标。

**信标**：刚解锁、还没建中转站的地图没有连通起点，会全图待机。解锁时自动落一座**不可拆除的小信标**作为临时源，建成中转站后可移除。

**判定**：从源出发，沿上下左右 BFS，只穿过 operational 建筑与已解锁格。不可达 → `standby`。

**待机效果**：产出归零、**能耗不计入需求**、维修与加成不生效、外观变暗。

**计算时机**：只在建筑集合变化时重算，缓存到 `map.connectivity`，不要每 tick 跑。`connected` 不持久化，加载后重算。

**边界**：核心恒连通；拆中间一座导致下游待机时必须明显提示；100 座设施下重算 < 5ms。

### 8.3 待机动画

精灵 60% 亮度、去饱和；每 40 帧闪一次 1px 琥珀点；不播产出粒子；`prefers-reduced-motion` 时只变暗。

### 8.4 提示与诊断

- 选中显示「待机 · 未接入网络」
- `diagnose.js` 增加「N 座设施未接入网络」
- 首次出现写一条日志
- 地图角标（与 §4 统一风格）

### 8.5 教程补一步

玩家建成第一座与核心不相邻的设施时提示：设施必须与运算中心连成一片才会运转，断开就待机。

> ⚠️ 镜面防御罩（§9）也需连通才生效——待机时护盾失效，这是有意的风险设计。

## 9. 新建筑：镜面防御罩（P1）

### 9.1 定位

第一个**纯防御型**设施。填补"后期建筑太贵，一次脉冲全清"的挫败感，同时给布局增加新的取舍：护盾本身很脆，且不保护自己。

### 9.2 规格

| 项 | 值 |
|----|-----|
| id | `mirrorShield` |
| 名称 | 镜面防御罩 |
| 类别 | 维护（maintenance） |
| 尺寸 | 1×1 |
| 成本 | 金属 120 · 芯片 30 · 稀土 40 |
| 建造时间 | 45 秒 |
| 能耗 | 4/s（**需连通**，待机则失效） |
| 耐久 | 120（刻意偏低） |
| 解锁 | `tech_hardening`（与加固工程同一条线） |
| 可堆叠 | 否（`stackable: false`） |

**效果**

> 为**周围 8 格**（含对角）的设施提供 **-6% 最终脉冲伤害**，可叠加，单格上限 **-45%**；对自身无效。

### 9.3 叠加与上限

```
shieldReduction(index) = min(0.45, 0.06 × 覆盖该格的镜面罩数量)
```

- 8 座罩包围一格才到 48% → 被 45% 上限截断，**防止无敌**
- 与"抗毁性累积 + 加固工程"合并时仍受 `getBuildingResistance` 的 **0.9 上限**约束：

```js
// state.js:835
const shield = getShieldAura(state, mapId, anchorIndex, depth); // 0 ~ 0.45
return Math.min(0.9, accumulated + fortification + shield);
```

**注意**：现在 `resistance` 已经是"减法减免"，直接加进同一项最省事，语义也一致（都是"少受多少比例伤害"）。

### 9.4 生效范围

| 灾变 | 是否生效 | 说明 |
|------|----------|------|
| 日冕脉冲 | ✅ | 主要目标 |
| 灰烬风暴腐蚀（`CORROSION`） | ✅ | 持续伤害同样减免 |
| 月背陨石（`HAZARD_DAMAGE`） | ✅ | 轨道/月背也可建 |
| 地下塌方（`COLLAPSE`） | ❌ | 塌方是结构问题，不是能量冲击 |
| 缺氧 / 断粮 | ❌ | 不是伤害 |

### 9.5 与堆叠风险的关系（必须写清）

脉冲伤害是：

```
amount = maxHp × (1 - resistance) × random(0.5~0.7) × 2^(count-1) × difficulty
```

`2^(count-1)` 增长极快（Lv.5 就是 ×16）。**护盾只减 6%/座，抵不过一层堆叠**。这是刻意的：

- 护盾的定位是"保护关键节点"，不是"让堆叠无风险"
- UI 里要把两项分开显示：`受击 ×1.6（堆叠） · 减免 18%（抗毁 6% + 护盾 12%）`
- 如果实测玩家觉得护盾没用，**优先提高单座数值（6% → 8%）**，不要动 `stackRisk` 公式

### 9.6 表现

- 精灵：半透明六边形镜面 + 中心青点，1px 描边
- 展开状态：选中时淡淡描出 8 格覆盖范围（青色虚线）
- 拦截脉冲：脉冲到达时护盾格闪一次白光，被保护建筑不抖
- 断电/待机：镜面变灰、范围虚线消失（明确"没电就不护"）

### 9.7 验收

- 相邻 8 格的建筑在脉冲中损失明显更小（用日志的"耐久损失 X%"对比）
- 两个罩覆盖同一格时减免叠加为 12%
- 罩断电后减免立刻为 0
- 罩自身不会被自己保护
- 选中罩时能看见 8 格范围
